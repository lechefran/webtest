## [0.5.0] - 2026-10-19

This is the first tagged release since `v0.2.0-beta.5`. It rolls up the v0.3 and v0.4 work
that was developed on branches but never published.

### Added

- `WebClientOptions.AllowedOrigins` restricts requests and redirects to explicit HTTP(S)
  origins, which protects against SSRF when URLs come from untrusted input.
- `WebClientOptions.RequestTimeout` sets an end-to-end request timeout. It defaults to 30s.
- `WriteHeaders`, `WriteRequest`, `WriteResponse` and `LogMetadata` file logging options.
- Per-request timing in the console summary: `total`, `connect` and `conn=reused`.
- `WebClient.CloseIdleConnections` and `WebClient.ClearGeneratedLogFilePath`.
- Package documentation and runnable examples on pkg.go.dev.
- CI (tests on Linux, macOS and Windows, plus `go vet`, `staticcheck` and CodeQL), Dependabot,
  and community health files.

### Changed

- **Breaking:** `ReadCsv(path)` now returns `([][]string, error)`.
- **Breaking:** `AddQueryParams(...)` now returns `(string, error)`.
- **Breaking:** `CloseResponse(...)` now returns `error`.
- **Breaking:** `Headers(...)` takes `map[string]string` instead of `*map[string]string`, and
  copies it.
- **Breaking:** `Options(...)` takes `WebClientOptions` instead of `*WebClientOptions`, and
  copies it.
- **Breaking:** Logging options were flattened into `WebClientOptions`, and the nested
  `WriteSettings` type was removed. Use `WriteHeaders`, `WriteRequest`, `WriteResponse` and
  `LogMetadata` directly.
- **Breaking:** Requests now use a 30 second end-to-end timeout unless `RequestTimeout` is set.
- The transport now clones Go's default `http.Transport`, so proxy, HTTP/2 and pooling defaults
  are preserved.
- Autogenerated log file names use a Windows-safe UTC timestamp.
- File write and close failures are returned as errors instead of exiting the process.
- Updated to Go 1.27.

### Removed

- **Breaking:** `HandleError` and the `DEFAULT`, `SOFT` and `STRICT` error modes. Errors are now
  returned directly.
- **Breaking:** The internal helpers `FormatStringArray`, `WriteToFile`, `CloseFile`,
  `SetHeaders`, `Transport` and `InitTransport` are no longer exported. Use `WebClient.Headers`
  to set headers. The client manages its transport internally.

### Fixed

- A response body resource leak in request execution.
- `..` segments in log file paths are rejected.
- Headers and options are safe to update concurrently with in-flight requests.
- A data race in per-request connect timing under concurrent use.
- The autogenerated log path notice printed `%!(EXTRA ...)` instead of the path.

## [0.2.0-beta.5] - 2025-03-24

- `Delete` uses query parameters, following HTTP semantics.
- Error handling modes for web client functions.
